Date Maths: the hero feature

Other tools make you set every photo to one fixed time — which destroys the order of a whole shoot. DateShift works the way the problem actually happened: your clock was off by an amount, so every photo is off by that same amount. Enter the offset once (say, −5 h 37 m for a clock that ran fast) and every photo moves by exactly that much. The gaps between your photos — the story of the day — stay exactly as shot.

  • Relative shift — one signed offset in seconds, applied to EXIF times and file times together
  • Preview before you commit — run Scan Only first: the diagnosis report lists every conflict (sources differing by more than 1 second) before anything is written
  • Sync all three sources — one checkbox writes the same corrected time into EXIF and file time, so your photo app, your file manager and your file names finally agree

Dual-camera sync — the part nobody else does for you

Two cameras at one event, two clocks, one timeline that doesn't line up. Every other tool makes you work out the difference by hand. DateShift does the arithmetic: pick one photo from each camera taken at the same moment, and it computes the offset and applies it to the whole second-camera folder. In our seeded test, camera B ran 83 seconds slow; DateShift computed 83.000 seconds and aligned all 3 second-camera photos to camera A's times with 0.000 s error.

Copies only — and a report that proves it

  • Originals never modified. DateShift only ever writes copies to a new output folder. In our own tests every original stayed byte-identical (SHA-256 verified).
  • Pixel data untouched. Only timestamps change. Decoded-pixel hashes were unchanged on all 10 processed files in the seeded test.
  • Every copy is re-read. The re-check report confirms EXIF and file time agree within 1 second — or flags the file instead of passing it.
  • Honest sources. A photo dated from its file name is labelled filename; a scanned photo with no date anywhere is labelled file_only and its file time is shifted without inventing an EXIF date.

Honest limits: JPEG and TIFF get full EXIF read and write. HEIC photos get diagnosis plus file-time and filename handling only — HEIC EXIF writes are reported as unsupported, never claimed. RAW formats (CR2, NEF, ARW, DNG and others) are reported as unsupported and skipped, not silently processed. Filename dates are read only from recognised patterns (IMG_YYYYMMDD_HHMMSS, YYYY-MM-DD_HH-MM-SS, YYYYMMDD_HHMMSS, YYYY-MM-DD, YYYYMMDD); an unrecognised name is treated as undated, not guessed. Shifting cannot recover a date that was recorded nowhere — in that case the report says so, and only the file time is shifted, labelled file_only.
